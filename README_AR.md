# ICT بالعربي 7.0 — تحديث 8C.8: إصلاح صورة Docker وفحص ما قبل النشر

## الخطأ المثبت
في Dockerfile المتوارث من 8C.3، جرى نسخ `server.js` ومحركات البيانات إلى الصورة، لكن **لم تُنسخ** `safety-gates.js` و`execution-quotes.js` اللتان أصبحتا مطلوبتين في 8C.4 و8C.5. لذلك، مع أن اختبارات Node المحلية تنجح، فإن تشغيل الصورة المبنية وفق Dockerfile القديم يؤدي إلى `MODULE_NOT_FOUND` عند إقلاع الخادم. إصلاح 8C.8 ينسخ هذين الملفين ويتحقق من تحميلهما **أثناء بناء الصورة**.

## محتويات ZIP (تحديث جزئي؛ لا يحل محل خدمة المراقبة كاملة)
- `monitor-service/Dockerfile`: إصلاح نسخ جميع وحدات وقت التشغيل والتحقق منها أثناء البناء.
- `monitor-service/package.json`: إضافة اختبار فحص النشر إلى `npm test` والأمر `npm run check:deploy`.
- `monitor-service/deployment-preflight.cjs`: فحص ملفات التشغيل المطلوبة، تعريف النسخ إلى Docker، إعداد حجم التخزين الدائم، عزل منفذ HTTP، إعداد نطاق CORS وربط HTTPS.
- `monitor-service/deployment-preflight.test.cjs`: اختبار حالات فقد الملف أو فقده من COPY، وفحص نجاح النسخة المجمعة.
- `README_AR.md`: هذا الدليل.

لا تتضمن الحزمة تعديلات على الواجهة أو Service Worker، ولا تمس حسابات المتداولين أو الصفقات أو التخزين المحلي.

## كيفية تطبيقها
1. احتفظ بالنسخة الكاملة من `monitor-service` حتى 8C.7، بما فيها جميع المحركات ووحدات الأخبار والتسعير وملفات compose وCaddy.
2. انسخ **الملفات الأربعة** داخل مجلد `monitor-service` في هذه الحزمة فوق نظائرها؛ لا تحذف الملفات الأخرى. لا ترفع أسرار `.env` إلى مستودع GitHub العام.
3. داخل مجلد الخدمة الكامل نفذ:

```bash
npm test
npm run check:deploy
```

4. على خادم VPS مملوك لك أو مفوض بإدارته، ضع إعدادات الإنتاج في `.env` **بصورة خاصة** بعد تحديد نطاق DNS حقيقي يشير إلى الخادم وتثبيت Docker Compose. ثم نفّذ (في مجلد الخدمة):

```bash
docker compose config --quiet
docker compose build --no-cache monitor
docker compose up -d
docker compose ps
docker compose logs --tail=80 monitor
```

5. بعد تفعيل HTTPS، راجع حالة الخدمة:

```bash
node readiness-check.cjs https://YOUR_MONITOR_DOMAIN
node stability-check.cjs https://YOUR_MONITOR_DOMAIN 3 10000
```

استبدل YOUR_MONITOR_DOMAIN بالنطاق الفعلي. عدم وجود `ECONOMIC_FEED_URL` أو `QUOTE_FEED_URL` مضبوطين يعني استمرار تعليق صلاحية تنفيذ الفرص. ولن تُستخدم هذه الخدمة لإجراء صفقات حقيقية أو إرسال توصيات معتمدة في هذا الإصدار.

## اختبارات أُنجزت هنا
- إعادة تجميع ملفات خدمة 8C.6 مع ترقيات 8C.7 ثم 8C.8 في مجلد اختبار كامل.
- تنفيذ `npm test`: **ثمانية اختبارات ناجحة** تشمل بوابات الأخبار، التسعير، صحة المراقبة، التعافي واختبار فحص النشر.
- تنفيذ `npm run check:deploy`: **passed=true**، دون أخطاء أو تحذيرات.
- لم تتوفر أداة Docker في بيئة الاختبار؛ لذلك **لم يُختبر بناء الصورة أو تشغيلها الفعلي**.
- لم يُنشر خادم VPS، ولم يُثبت تشغيل مستمر أو اتصال بمزود أسعار تنفيذي أو أخبار مرخص.

## الخطوة اللاحقة
عند توفر خادم وعنوان HTTPS، نفّذ أوامر الاختبار أعلاه واستخدم النتائج الفعلية لتحديد مشاكل الاتصال أو بيانات الأسواق. لا يمكن وصف الخدمة بأنها تعمل 24/7 قبل نشرها ومراقبتها فترة كافية.
