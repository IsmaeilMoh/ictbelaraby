# ICT بالعربي 7.0 — تحديث 8C.3: تجهيز خدمة المراقبة للنشر الدائم

## ما أنجزه التحديث
- ملفات Dockerfile وDocker Compose وخادم Caddy للحصول على HTTPS تلقائي عبر اسم نطاق تملكه وتضبط DNS له.
- وحدة تخزين Docker دائمة لحفظ المراقبات البحثية بين إعادة تشغيل الحاوية.
- استعادة سجل المراقبة بعد إعادة تشغيل الخدمة (مع بقاء البيانات القديمة قديمة حتى دورة فحص جديدة).
- تصحيح استجابة `/health` لإرجاع فترة الفحص الحقيقية `pollIntervalMs`، وإظهار آخر فحص بتوقيت نيويورك وفلسطين داخل المركز.
- لا تغيير في استراتيجيات ICT أو حدود المخاطرة أو تصميم الموقع.

## فصل التركيب
**ملفات GitHub Pages (جذر المستودع):** `decision-center.html` و`ict-background-status-708c2.js` و`sw.js` فقط.
**ملفات الخادم (استضافة Node على VPS):** ضع مجلد `monitor-service/` في مستودع خاص أو على خادم مستقل، ولا ترفع ملفات .env الفعلية للمستودع العام.

## خطوات تشغيل الخدمة على VPS يعمل Linux وDocker Compose
1. اشترِ/استخدم استضافة VPS تعمل باستمرار، مع عنوان IP عام، وافتح المنفذين 80 و443 حسب الحاجة.
2. أنشئ سجّل DNS من النوع A لاسم نطاق/نطاق فرعي تملكه (مثل monitor.yourdomain.tld) يوجّه إلى IP الخاص بالخادم. لا تستخدم monitor.example.com حرفيًا.
3. ثبّت Docker Engine وCompose على الخادم وفق وثائق Docker الرسمية.
4. انقل مجلد `monitor-service/` إلى الخادم باستخدام وسيلة نقل آمنة.
5. نفّذ داخل المجلد: `cp .env.deploy.example .env`، ثم عدّل `MONITOR_DOMAIN` في ملف `.env` إلى نطاقك الحقيقي.
6. اختبر من داخل المجلد: `docker compose config`، ثم `docker compose up -d --build`، ثم `docker compose logs -f --tail=100`.
7. بعد اكتمال أول دورة فحص، افتح `https://MONITOR_DOMAIN/health` وتحقق من `active=true` و`cycleCount>0`.
8. افتح صفحة مركز التوصيات في الموقع، واكتب `https://MONITOR_DOMAIN` في لوحة «مراقبة الأسواق بالخادم» ثم اضغط «اختبار الاتصال».

## أمور مهمة
- لا نملك صلاحية إنشاء VPS/DNS في حسابك من هذه المحادثة؛ الحزمة **جاهزة للنشر** لكنها ليست خادمًا منشورًا بالفعل.
- GitHub Pages لا يشغّل Node.js. الخدمة لا تعمل بعد رفع ملفات GitHub فقط.
- حظر CORS لا يمنع الوصول المباشر إلى واجهات عامة. `/health` و`/snapshot` عامتان للقراءة؛ لا تحتويان مفاتيح حسابات أو بيانات صفقات شخصية. لا تُضف مفاتيح داخلها.
- يجب مراجعة تراخيص إعادة نشر بيانات أي مزود، وخاصة Biquote، قبل تشغيلها للجمهور.
- تكون مراقبات الخادم بحالة **research_only_blocked** لأن الأخبار والمخاطرة وBid/Ask والفحص الأمامي غير مكتملة.
- يلزم الاحتفاظ بنسخ احتياطية من وحدة تخزين Docker (monitor-data)، ومراقبة أخطاء الاتصال، وحماية الخادم وتحديثه دوريًا.
- تأكد من دقة التاريخ والساعة (NTP) على VPS لأن اختبار حداثة الشموع يعتمد عليه.

## فحوص هذه الحزمة
- `cd monitor-service && npm test` (بيانات محاكاة).
- `node --check monitor-service/server.js` و`node --check ict-background-status-708c2.js`.
- التحقق من وجود ملفات Docker/Caddy، وسلامة ZIP، وسلامة مراجع صفحة الموقع.
- **لم أتمكن من نشر VPS فعليًا أو اختبار مرور البيانات في الإنتاج دون دومين واستضافة مملوكين لك.**

## الخطوة التالية بعد التشغيل
تحقق من وصول البيانات الحقيقية لعدة ساعات واستقرار الاتصال، ثم نبدأ تطوير التكامل الخلفي لفحص الأخبار وقواعد المخاطرة دون نشر معلومات الحسابات الخاصة.
