## إعداد اختياري لتغذية الأسعار التنفيذية
في متغيرات بيئة الخادم الخاص (وليس ملفات الموقع) عيّن:
- `QUOTE_FEED_URL=https://your-licensed-provider.example/quotes.json`
- `QUOTE_MAX_AGE_MS=30000`
- `QUOTE_MAX_SPREAD_BPS=40`

يجب أن يُرجع `QUOTE_FEED_URL` استجابة JSON بالصيغة التالية (مثال بنيوي فقط، **ليس عرض سعر حقيقيًا**):
```json
{"quotes":[{"id":"metals:XAUUSD:15","bid":4000.0,"ask":4000.2,"timestamp":"2026-11-24T12:00:00Z","source":"licensed-provider"}]}
```
**لا بد من قيم فعلية محدثة عند الطلب**؛ أي تاريخ قديم أو مصدر غير معروف أو زوج أسعار متناقض يرفضه الفاحص. المراقب لا يمنح أي فرصة `readyForExecution=true` حتى مع اتصال الأسعار. معرف `id` يطابق فئة الأصل ورمزه وإطار الشموع المستعمل في المراقب. وضع الرمز الخاطئ أو مزود يقتبس أداة مختلفة يلغي إمكانية الاعتماد. تأكد من ترخيص المزود وإمكانية الوصول إلى API وتنظيم أسواق النقد/العقود عند اختيار مصدر الأسعار.

من دون هذه التغذية، تظهر حالة الأسعار التنفيذية «غير متاحة» ولا تتولد أسعار وهمية. الأسعار المعروضة هي فقط لأغراض تدقيق جودة المصدر وليست عرضًا قابلًا للتنفيذ لدى وسيط المستخدم؛ قد تتغير فورًا ويتعين إعادة التحقق منها قبل التنفيذ.

## الاختبار
1. ارفع ملفات الموقع الأربع.
2. افتح `decision-center.html#dc-execution-safety-8c5` واختر حسابًا موجودًا ومبلغ مخاطرة مناسبًا؛ اضغط الفحص المحلي.
3. اضغط فحص التسعير؛ من الطبيعي ظهور «غير متاح» إذا لم يكن VPS أو مزود السعر منشورًا.
4. إن كنت تستخدم الخادم، عدّل `.env` الخاص عليه وأعد بناء وتشغيل Docker Compose.
5. داخل `monitor-service` نفّذ `npm test` للتحقق من السلوك المنطقي.
6. بعد تحديث التطبيق على GitHub، أغلق الصفحة وأعد فتحها بعد اكتمال تنشيط Service Worker.

## حدود الإنجاز
- لا ننقل بيانات الحسابات من الجهاز إلى VPS، ولا يوجد مزامنة للحسابات بين الأجهزة.
- فحص حدود شركات التمويل محلي وتقديري، وليس مراجعة موثقة لشروط شركة التمويل.
- واجهة السعر على الخادم اختيارية ولا توجد تغذية Bid/Ask تنفيذية مرخصة مُفعلة في هذا ZIP.
- لا توجد موافقة تنفيذ، ولا فتح صفقات، ولا ضمان ربحية، ولا Push.
- الاختبارات هنا برمجية/محلية؛ لم يتم نشر خادم VPS أو إجراء اختبار Live على موقع GitHub بعد.
