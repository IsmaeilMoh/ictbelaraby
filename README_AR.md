# ICT بالعربي 7.0 — 8C.7: اختبار الاستقرار والتعافي من انقطاع الأسعار

## ماذا يصلح التحديث؟
بعد 8C.6 كان `/health` يميّز بين نشاط الخدمة وصلاحية البيانات، لكنه لا يعرض مدة تكرر فشل أصل معين أو توقيت عودة المصدر. يضيف 8C.7 عداد إخفاقات متتالية لكل أصل، وتاريخ آخر شمعة صحيحة، وتاريخ التعافي عند عودة المصدر بعد إخفاق. هذه معلومات تشخيصية وليست توصيات شراء/بيع.

## تركيب ZIP الجزئي فوق 8C.6
**جذر GitHub Pages:** استبدل `ict-background-status-708c2.js` و`sw.js` فقط. لم تتغير ملفات الواجهة الرئيسية أو بيانات الحسابات والصفقات.

**خادم VPS (مجلد monitor-service):** استبدل `server.js` و`package.json` وأضف `recovery.test.cjs` و`stability-check.cjs` و`stability-check.test.cjs`. احتفظ ببقية ملفات خدمة 8C.6 بما فيها محركات الأسعار وICT وبوابات الأخبار وBid/Ask. لا ترفع ملفات الخادم ومفاتيحه السرية إلى مستودع الواجهة العامة.

## الفحوص
داخل مجلد خدمة المراقبة الكامل نفّذ:

```bash
npm test
```

يشمل الاختبار الجديد: انقطاع متكرر في Bybit مصطنع، متابعة عداد الإخفاقات، استعادة المصدر، إعادة تعيين العداد وتسجيل وقت التعافي، حفظ النتائج، وإبقاء `readyForExecution=false`.

بعد نشر الخدمة فعليًا عبر HTTPS يمكنك إجراء **اختبار استقرار متعدد العينات**:

```bash
node stability-check.cjs https://monitor.example.com 3 10000
```

العنوان أعلاه مثال؛ استخدم دومينك. يأخذ هذا الأمر 3 قراءات يفصل بينها 10 ثوانٍ؛ يُرجع 0 إذا **كانت كل القراءات** تملك دورة مراقبة حديثة وبيانات صالحة لأصل واحد على الأقل، و1 عند وجود فشل في أي عينة، و2 عند خطأ إعداد. لا يثبت هذا استقرار 24/7 ولا جاهزية التنفيذ؛ يظل يلزم مراقبة طويلة المدى تشمل كل أصل.

## حالة الواجهة
داخل لوحة **مراقبة الأسواق بالخادم** في مركز التوصيات تظهر أعداد الإخفاقات المتتالية وحالة التعافي لكل أصل عندما تستجيب الخدمة. حالة «متصل» لا تعني صلاحية جميع الأسواق؛ تابع ملخص السوق وحالة كل أصل.

## نتائج الفحص المنجز هنا
- جميع الاختبارات السبعة في `npm test` نجحت في بيئة Node.js المحلية باستخدام بيانات مصطنعة.
- لم يُنشر خادم VPS حقيقي، ولم تتصل هذه الاختبارات بخادم المراقبة من موقع GitHub Pages.
- لا يوجد مزود Bid/Ask تنفيذي موصول؛ لا توجد موافقة تنفيذ أو Push أو تداول فعلي.

## ما بعد ذلك
تفعيل VPS حقيقي وربط DNS وHTTPS ومزودي الأخبار وأسعار التنفيذ، ثم اختبار الاستقرار لمدة كافية وفحص جودة البيانات لكل أصل. لا تضع أي أسرار في مستودع GitHub Pages.
