# ICT بالعربي 7.0 — التحديث 8C.2: خدمة مراقبة بحثية بالخلفية

## النطاق الفعلي
تم إعداد خدمة Node.js مستقلة يمكن تشغيلها على خادم دائم لجلب شموع مكتملة بصورة دورية من Bybit USDT والكشف عن الشموع التقليدية المتاحة من Biquote (مصدر مستقل)، وتشغيل محرك 2D/2E نفسه لاكتشاف نماذج Sweep → MSS → FVG على بيانات مكتملة، وحفظ سجل البحث في ملف JSON محلي على الخادم. لا توجد أوامر تداول أو إشارات تنفيذ معتمدة أو Push في هذه النسخة.

## ملفات النشر (GitHub Pages)
- `decision-center.html`: لوحة حالة خدمة المراقبة في مركز التوصيات، ولا تؤثر في عمليات الفحص السابقة.
- `ict-background-status-708c2.js` و`ict-background-status-708c2.css`: واجهة فحص اتصال الخدمة، مع تقييد عنوان الخادم البعيد لـ HTTPS.
- `sw.js`: تحديث كاش الـPWA لظهور اللوحة.

## ملفات الخدمة المستقلة
المجلد `monitor-service/` يحتوي الشفرة اللازمة للتشغيل المستقل، ويشمل نسخًا من محركَي 2D و2E المستخدمين في المشروع لتشغيلهما على Node.js، دون تغيير النسخ المستخدمة في موقع الويب.

**مهم:** رفع ملفات الخدمة إلى GitHub Pages **لا يشغّلها**. يجب نشر مجلد `monitor-service/` بشكل منفصل على خادم Node.js مستمر التشغيل. والأفضل الاحتفاظ بملفات تشغيل الخادم في مستودع خاص؛ لا تضع أي ملفات `.env` حقيقية أو كلمات مرور أو مفاتيح في المستودع العام.

## تشغيل اختباري على جهاز أو خادم Node.js 20+

```bash
cd monitor-service
npm test
npm start
```

ثم افتح `http://127.0.0.1:8787/health` أو `/snapshot` من جهاز الخدمة نفسه.

الإعدادات عن طريق متغيرات البيئة:
- `MONITOR_TARGETS=crypto:BTCUSDT:15,crypto:ETHUSDT:15,metals:XAUUSD:15,forex:EURUSD:15`
- `POLL_MS=300000` (الحد الأدنى 60000 مللي ثانية)
- `STORE_FILE=/path/on/persistent-volume/monitor-data.json`
- `HOST=127.0.0.1`, `PORT=8787`
- `ALLOWED_ORIGIN=https://ismaeilmoh.github.io` (يطبّق CORS فقط على المنشأ المسموح)

عند الاستضافة العامة يلزم **HTTPS** عبر reverse proxy ووصول مستقر للخدمة وقرص تخزين دائم، وإعداد تشغيل تلقائي/إعادة تشغيل عند الفشل. لا تستخدم `HOST=0.0.0.0` مباشرة دون حماية طرفية، وقيّد معدل الاستدعاءات في الـreverse proxy وتحقق من شروط المزود قبل إعادة نشر البيانات.

بعد ذلك اكتب رابط الخدمة المنشورة بنظام HTTPS في لوحة «مراقبة الأسواق بالخادم — 8C.2» داخل `decision-center.html` واضغط «اختبار اتصال الخدمة».

## ماذا سيرى المستخدم؟
- بدون خادم: لوحة جديدة تعرض حالة «غير متصلة»، ولا تدعي وجود مراقبة مستقلة.
- مع تشغيل الخادم: آخر دورة مسح وعدد الأصول وحالة جودة شموع كل أصل؛ وتعرض الأخطاء والفجوات/التأخير إذا حدثت.
- لن تُعرض «توصية جاهزة» من هذه الخدمة. جميع الأحداث المكتشفة لها حالة `research_only_blocked` بسبب غياب تدقيق الأخبار والحساب وBid/Ask.

## ما لم ينفذ
- لم يُنشر خادم تشغيل دائم نيابة عن صاحب الموقع.
- لا Web Push أو إشعارات عند إغلاق التطبيق.
- لا Bid/Ask ولا تنفيذ ولا حجم عقد أو ربط حساب تداول بالخادم.
- لا ضمان لتوفر Biquote أو رخصة إعادة نشر بياناته؛ عند فشل المصدر تعرض الخدمة حالة `blocked`.
- لا تعتمد نتائج الاختبار المحلي كإثبات لربحية أو صلاحية النماذج في السوق الحي.

## الاختبارات المنفذة
- `node --check` لملفات JS الجديدة.
- `npm test`: فحص الرموز والأطر، رفض بيانات ناقصة أو متقطعة، دورة مراقبة باستخدام استجابة Bybit محاكية، حفظ JSON، وحالة عدم الجاهزية التنفيذية.
- فحص بنية ZIP والصفحة وحفظ CSS/JS دون تغيير الهيدر والتذييل.
- **لم ينجز** تشغيل الإنتاج على خادم مستقل أو اختبار وصول المصادر الحية من شبكة موقعك.

## الخطوة القادمة
تشغيل الخدمة واختبارها على استضافة مناسبة، ثم ربط تقويم الأخبار ومخاطرة الحساب عبر خادم آمن، ومزود أسعار تنفيذية مرخص، وتقييم إشاراتها أماميًا قبل الاعتماد العام.
