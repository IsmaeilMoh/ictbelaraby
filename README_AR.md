# ICT بالعربي 7.0 — تحديث 8C.6: صحة التشغيل وجاهزية بيانات السوق

## الهدف
إصلاح نتيجة مضللة في مراقبة 8C.5: اكتمال دورة الفحص لا يعني وصول شموع حديثة صالحة. إذا توقفت جميع مصادر الأسعار فقد تبقى الخدمة `active=true`، لكن تصبح `marketDataReady=false` و`allMarketDataReady=false`، وتعرض الواجهة تنبيهًا واضحًا.

## ملفات الموقع — إلى جذر GitHub Pages
- `ict-background-status-708c2.js` (استبدال): إظهار عدد الأصول الصالحة والمحجوبة وغير المفحوصة والقديمة، والتمييز بين اتصال الخدمة وصحة بياناتها.
- `sw.js` (استبدال): تحديث رقم كاش التطبيق مع إبقاء بقية الموارد والتصميم كما هما.

## ملفات VPS — داخل مجلد monitor-service فقط
- `server.js` (استبدال): إضافة `marketSummary` و`marketDataReady` و`allMarketDataReady` و`cycleError` إلى `/health` و`/snapshot`، مع عدم اعتبار الخادم جاهزًا للتنفيذ مطلقًا.
- `package.json` (استبدال): تضمين اختبارات جاهزية التشغيل وأعطال السوق في `npm test`.
- `readiness-check.cjs` (جديد): فاحص مستقل لخدمة HTTPS منشورة بالفعل.
- `readiness-check.test.cjs` و`operational-health.test.cjs` (جديدان): اختبارات محلية دون اتصال بالسوق.

لا تعدل ملفات `decision-center.html` أو بيانات الصفقات أو الحسابات. لا ترفع ملفات خادمك الخاصة أو أي مفاتيح اتصال إلى مستودع GitHub Pages العام.

## اختبار محلي دون خادم منشور
داخل `monitor-service` نفّذ:
```sh
npm test
```
تشمل الاختبارات السابقة للشموع والأخبار وBid/Ask، وتضيف التحقق من حالات: لا فحص بعد، تعطل جميع مصادر السوق، دورة نشطة بلا بيانات، منع تصريح التنفيذ، ورصد تحديث النتائج.

## بعد نشر خدمة Node.js على VPS
```sh
node readiness-check.cjs https://monitor.your-domain.example
```
يتصل الفاحص بواجهة `/health` العامة عبر HTTPS ويرجع JSON مفصلًا. يُرجع exit code 0 عند سلامة دورة المراقبة وتوافر **بيانات حديثة لأصل واحد على الأقل**، و1 عند تعطل البيانات، و2 عند فشل الاتصال أو عنوان غير صالح. سيُحذر حتى عند نجاح بيانات السوق إذا بقيت الأجندة أو أسعار Bid/Ask غير موثقة. هذا **ليس** تصريح جاهزية للتوصيات أو التنفيذ. راجع `marketSummary` لكل أصل قبل اعتبار المراقبة شاملة.

## ما لم يُنفذ أو يُختبر
- لا توجد استضافة VPS أو اسم DNS أو مصدر اقتصادي أو مزود Bid/Ask مرخص مربوط في هذه الحزمة.
- لم يتم إجراء اختبار شبكة حي من موقع GitHub Pages إلى خادم منشور؛ الاختبارات محلية وببيانات اصطناعية فقط.
- لم تُفعّل تنبيهات Push أو أوامر التداول أو موافقة مخاطرة الحساب على الخادم.
- لا تختبر الحزمة Docker لأن Docker غير مثبت في بيئة البناء الحالية.

## لماذا يهم ذلك؟
يمكن أن تُظهر الخدمة أنها نشطة لأنها تحفظ دورة فارغة أو فاشلة. بعد هذا التصحيح، تشير اللوحة إلى نقص صلاحية الشموع بدل أن يوحي نجاح الاتصال بنجاح مراقبة الأسواق. يحتفظ المركز بنفس التصميم والأقسام الحالية.
