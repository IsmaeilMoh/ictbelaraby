# ICT بالعربي 7.0 — التحديث 8C.10 (مراقبة بحثية مجانية عبر GitHub Actions)

**ميزانية الاستضافة المطلوبة لهذا المسار: صفر دولار** للمستودع العام باستخدام GitHub-hosted standard runner وفق شروط GitHub الحالية. ليست خدمة لحظية، وقد تتأخر الجدولة أو تتوقف؛ ولا توجد إشعارات خلفية أو موافقة تنفيذ صفقات.

## المتطلبات
- لديك النسخة السابقة مركبة حتى 8C.8 (واجهة الموقع + مجلد monitor-service كامل). التحديث ZIP **جزئي** ولا يغني عن النسخ السابقة.
- المستودع العام: `ismaeilmoh/ictbelaraby`، الفرع الافتراضي المستخدم للموقع. ضع ملف Workflow في الفرع الافتراضي نفسه.
- في GitHub: Settings → Actions → General → Workflow permissions → **Read and write permissions**؛ إن منع مالك المستودع هذه الصلاحية، ستفشل مهمة النشر وتحتاج تعديل الإعدادات.
- لا تضف مفاتيح خاصة إلى الملفات المنشورة. `ICT_ECONOMIC_FEED_URL` و`ICT_QUOTE_FEED_URL` اختياريان في Repository variables، ويجب ألّا يحتويا أسرارًا في العنوان؛ لا ينصح بربط مصدر سري بهذه الطريقة. عند غيابهما تبقى بوابات الأخبار والاقتباسات معلقة.

## الملفات الخمسة الرئيسية في ZIP
1. `.github/workflows/ict-free-market-monitor.yml` — تشغيل كل 15 دقيقة تقريبًا (الدقائق 7، 22، 37، 52)، مع تشغيل يدوي `workflow_dispatch`.
2. `monitor-service/github-run-once.cjs` — مهمة تفحص الأسواق مرة واحدة ثم تتوقف وتكتب نتيجة **بحثية فقط**.
3. `monitor-service/github-run-once.test.cjs` — اختبار صارم لصحة نشر بيانات غير تنفيذية.
4. `monitor-service/package.json` — إضافة أوامر `run:once` و`test:actions` دون حذف الاختبارات السابقة.
5. `decision-center.html` و`ict-background-status-708c2.js` و`sw.js` — ربط الواجهة بزر قراءة التقرير المجاني وتحديث الكاش.

## التركيب
1. افتح ZIP، وانسخ الملفات إلى **نفس المسارات** داخل المستودع؛ لاحظ أن `.github` مجلد مخفي.
2. في واجهة GitHub: Actions → **ICT Arabic - free periodic market research** → Run workflow. العملية تستغرق وقتًا بحسب استجابة مصادر الأسعار؛ راجع سجل التنفيذ.
3. تُنشر النتيجة تلقائيًا في فرع منفصل اسمه `ict-monitor-feed`، في `monitor-status.json`. لا يتغير فرع الموقع، ولا يتغير إعداد GitHub Pages.
4. رابط النتيجة العام: `https://raw.githubusercontent.com/ismaeilmoh/ictbelaraby/ict-monitor-feed/monitor-status.json`.
5. افتح `https://ismaeilmoh.github.io/ictbelaraby/decision-center.html#dc-background-8c2`، واضغط **قراءة أحدث فحص مجاني من GitHub Actions**.
6. إذا ظهر الملف 404، راجع Workflow permissions وسجل Actions. قد يمنع GitHub عمليات الدفع بالقوة إلى فرع محمي؛ لا تحمِ الفرع `ict-monitor-feed` أو غيّر أسلوب النشر.

## آلية حفظ السجل
- يُستعاد `monitor-state.json` من فرع `ict-monitor-feed` قبل كل فحص للحفاظ على عدادات الانقطاع والنتائج البحثية.
- يُنشر الفرع عن طريق استبدال آخر لقطة واحدة باستخدام `git push --force` **إلى فرع ict-monitor-feed فقط**. لا يُعدَّل `main` ولا تتولد مئات الالتزامات في سجل الموقع الرئيسي.
- الفرع عام ويمكن للآخرين قراءة تقرير الأسواق والسجل البحثي. **لا تضع أي بيانات شخصية أو مفاتيح سرية في ملف حالة المراقبة.**
- تعرض الواجهة النتائج غير صالحة بعد مرور 45 دقيقة على الفحص؛ الحد يصلح للتمييز بين انقطاع الجدولة والتحديث المعتاد، لا لتقدير السعر اللحظي.

## القيود والصدق التقني
- فحوص GitHub Actions الدورية هي **best effort**. وقد تتأخر أو تُفقد، وتتوقف في المستودعات العامة بعد 60 يومًا من عدم نشاط المستودع. الاستمرار 24/7 غير مضمون.
- لا تُرسل إشعارات push عند إغلاق التطبيق، ولا يُصدر التقرير توصيات تنفيذية، ولا يُنشئ أوامر تداول.
- بدون مصدر أخبار متصل تظل بوابة الأخبار معلقة؛ بدون أسعار Bid/Ask لا توجد موافقة تسعير؛ حساب المتداول يبقى على جهازه.
- فشل بيانات السوق يجعل `marketDataReady=false`؛ لا يُختلق نجاح من مجرد اكتمال المهمة.
- استجابة `raw.githubusercontent.com` قد تتأخر في انتشارها بسبب ذاكرة CDN؛ تُقارن الواجهة وقت الفحص الفعلي، ولا تثق فقط بوقت تحميل الملف.
- إذا كان المستودع **خاصًا** أو تغيّرت شروط GitHub، تحقق من قيود الاستخدام والتكلفة أولًا.

## الاختبارات المحلية
من داخل `monitor-service` الذي يحتوي محركات المشروع كاملة:

```bash
npm test
npm run test:actions
```

هذه النسخة ليست تأكيدًا على وجود Workflow منشور بالفعل؛ يجب رفع الملفات وتشغيل المهمة يدويًا ثم التحقق من نتيجة Actions والفرع الجديد.
